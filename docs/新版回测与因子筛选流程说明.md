# 新版回测与因子筛选流程说明

本文档用于说明 QuantaAlpha 新版因子评估链路，即 `oto_single_factor_v1`。新版的核心变化是：因子生成、表达式解析、`result.h5` 产出方式保持不变；因子质量评估改为每个因子独立进行 OTO 单因子评估，不再训练 LightGBM，也不再把多个因子合成为组合因子后统一回测。评估结果写入因子库字段 `evaluation_v2`，旧版 `backtest_results` 仅作为 `qlib_legacy` 保留。

相关实现与配置：

- 配置文件：`configs/evaluation.yaml`
- 评估引擎：`quantaalpha/evaluation/engine.py`
- 因子库评估服务：`quantaalpha/evaluation/service.py`
- 防未来审计：`quantaalpha/evaluation/lookahead.py`
- 去重服务：`quantaalpha/evaluation/dedup.py`
- 设计决策：`docs/ADR-OTO单因子评估.md`

## 1. 总体流程

新版流程可以概括为：

```text
因子生成/进化
  -> 生成单因子表达式与 factor.py
  -> 执行 factor.py 得到 result.h5
  -> 防未来审计
  -> 与公司 OTO 收益标签按交易日历对齐
  -> 训练期单因子评估
  -> 训练期硬门槛筛选
  -> 训练通过后执行 2025H2 验证
  -> 写入 evaluation_v2
  -> 批次内相似因子去重
  -> 人工确认后归档重复因子
```

在进化过程内，`OTOSingleFactorRunner` 会逐个评估本轮生成的因子，并选择一个 `primary_factor` 作为该轮代表。选择顺序为：

```text
训练是否通过 -> 训练期超额 Sharpe -> abs(IC) -> 多空收益差
```

在因子库后处理场景中，可以用 CLI 对 `all_factors_library*.json` 中尚未评估或全部因子重新评估。

## 2. 数据来源与样本空间

### 2.1 因子值

因子生成阶段仍沿用现有 Qlib / HDF5 数据链路。每个因子执行后应产出 `result.h5`，其索引要求为两层 MultiIndex：

```text
(datetime, instrument)
```

`result.h5` 的生成逻辑是：

```text
读取 daily_pv.h5
  -> 将因子表达式中的 $open/$close/$high/$low/$volume 等变量替换为 daily_pv.h5 中对应列
  -> 执行表达式，得到每个 (datetime, instrument) 上的因子值
  -> 将结果按原索引写入 result.h5
```

也就是说，生成阶段不会把日期整体前移或后移。`result.h5` 中日期为 `t` 的因子值，继承 `daily_pv.h5` 中日期 `t` 的索引，表示股票在 `t` 这一天的因子观测值：

```text
result.h5[t, i] = Factor_i(t)
```

如果表达式直接使用 `$open`、`$high`、`$low`、`$close`、`$volume` 等日线字段，则 `Factor_i(t)` 可能包含 `t` 当日完整日线信息，因此应视为 `t` 收盘后才完整可知的信号。若表达式使用滚动窗口或滞后函数，例如 `TS_MEAN($close, 20)`、`DELAY($close, 1)`，则日期仍然是 `t`，只是数值内部使用了截至 `t` 或 `t-1` 的历史数据。

因此，`result.h5` 的 `datetime` 不是交易入场日，也不是收益标签日，而是因子观测日 `factor_date`。新版评估会在后续时间对齐环节统一使用：

```text
Factor_i(t-1) -> entry open(t)
```

评估时会标准化为：

```text
factor_date, code, factor_value
```

其中 `instrument` 会被转换为 6 位股票代码。例如：

```text
SH600000 -> 600000
600000.SH -> 600000
600000 -> 600000
```

### 2.2 行情与收益标签

`evaluation_v2` 的 OTO 行情不使用 Qlib，而是从公司 Mongo 数据源读取：

- 交易日历：`Index_DayLine` 中 `000852.SH` 的交易日。
- 股票日线：`Stock_DayLine_{year}`。
- ST 信息：`stock_bak_daily_{year}`，如果集合存在则用于 ST 过滤。

评估范围只保留沪深 A 股主板、科创板、创业板等符合代码规则的股票，不包含北交所。默认过滤：

- ST 股票。
- 开盘涨停或跌停股票。
- 缺少 `open`、`close`、`pre_close` 或下一交易日行情的样本。

开盘涨跌停判断使用股票代码对应涨跌停比例：

```text
limit_ratio(code) =
  20%, if code starts with 300, 301, 688, 689
  10%, otherwise
```

```text
upper_limit(t) = round(pre_close(t) * (1 + limit_ratio), 2)
lower_limit(t) = round(pre_close(t) * (1 - limit_ratio), 2)
open_limit(t) = open(t) >= upper_limit(t) - 0.001
             or open(t) <= lower_limit(t) + 0.001
```

## 3. 时间对齐规则

新版最重要的约束是信号、交易、收益必须按市场交易日历对齐，不能按个股下一条可用行情跨越停牌日。

对任意交易日 `t`：

```text
factor_date = previous_market_session(t)
entry_date  = t
exit_date   = next_market_session(t)
```

也就是：

```text
F(t-1) -> open(t) -> open(t+1)
```

这样做的原因是 `result.h5` 中日期 `t-1` 的因子值通常要等 `t-1` 收盘后才完整可知；把它用于下一市场交易日 `t` 的开盘交易，可以避免把当日收盘信息错误用于当日开盘。

必须满足：

```text
factor_date < entry_date < exit_date
```

如果某只股票在 `exit_date` 没有行情，则该样本直接剔除，不能跳到该股票复牌后的下一条记录。春节等长假也是按市场交易日历连接。

## 4. OTO 收益标签

公司 OTO 收益定义为：

```text
OTO(t, t+1) = close(t) / open(t) * open(t+1) / pre_close(t+1) - 1
```

其中：

- `open(t)`：入场日开盘价。
- `close(t)`：入场日收盘价。
- `open(t+1)`：下一市场交易日开盘价。
- `pre_close(t+1)`：下一市场交易日前收盘价，理论上对应 `close(t)`，但以数据源字段为准。

这个标签可以理解为：

```text
日内收益 * 隔夜开盘跳空收益 - 1
```

即从 `open(t)` 到 `close(t)`，再从 `pre_close(t+1)` 到 `open(t+1)` 的连续收益。

## 5. 训练期、验证期与封存期

默认配置为：

```text
训练期：2023-01-01 至 2025-06-30
验证期：2025-07-01 至 2025-12-31
2026：sealed，不读取、不计算、不反馈给 AI
```

收益样本的 `entry_date` 和 `exit_date` 必须同时位于所属区间内。例如训练期样本要求：

```text
2023-01-01 <= entry_date <= 2025-06-30
2023-01-01 <= exit_date  <= 2025-06-30
```

验证期不是硬淘汰门槛。默认只有训练期通过的因子才会继续跑验证期，验证结果用于观察训练到验证的保留率和退化率。

## 6. 防未来审计

每个因子进入评估前先做防未来审计。审计失败的因子状态为 `lookahead_rejected`，不会进入回测。

### 6.1 静态检查

静态检查会解析因子表达式和 `factor.py`，拒绝明显使用未来数据的写法，包括：

- `DELAY`、`DELTA`、`TS_PCTCHANGE` 使用负周期。
- pandas 方法 `shift`、`diff`、`pct_change` 使用负周期。
- 读取非标准外部数据，如 `read_csv`、`read_parquet`、`read_pickle`、`read_json`。
- 读取非标准 HDF5 文件，`read_hdf` 只允许读取 `daily_pv.h5`。
- 使用 `pymongo`、`requests`、`httpx`、`urllib`、`qlib.data` 等外部数据入口。

### 6.2 截断重跑检查

在训练历史的 25%、50%、75% 分位截点截断 `daily_pv.h5`，重新运行 `factor.py`。对每个截点 `c`，要求：

```text
factor_full(c, i) == factor_truncated_to_c(c, i)
```

比较使用：

```text
np.allclose(expected, actual, rtol=1e-8, atol=1e-10)
```

含义是：未来数据被删除后，截点当天的因子值不能变化。如果变化，说明因子计算依赖了截点之后的信息。

## 7. IC 与方向标准化

每日 Pearson IC 定义为横截面相关：

```text
IC_t = Corr_i(F_{t-1,i}, R^{OTO}_{t,i})
```

其中：

- `F_{t-1,i}` 是股票 `i` 在上一市场交易日的因子值。
- `R^{OTO}_{t,i}` 是股票 `i` 在 `t -> t+1` 的 OTO 收益。

训练期平均 IC：

```text
mean_IC = mean_t(IC_t)
```

训练期 IC 标准差：

```text
std_IC = std_t(IC_t)
```

非年化 ICIR：

```text
ICIR = abs(mean_IC) / std_IC
```

RankIC 与 RankICIR 使用 Spearman 相关：

```text
RankIC_t = SpearmanCorr_i(F_{t-1,i}, R^{OTO}_{t,i})
RankICIR = abs(mean_t(RankIC_t)) / std_t(RankIC_t)
```

方向只在训练期确定一次：

```text
direction_multiplier =
  -1, if mean_IC < 0
   1, otherwise
```

方向标准化后的因子值为：

```text
F^*_i = direction_multiplier * F_i
```

训练分组、验证分组和 IC 衰减都使用这个固定方向。验证期不得重新选择方向。

## 8. 十分组收益与多空收益差

每天对方向标准化后的因子值 `F^*` 做十分组：

```text
G0, G1, ..., G9 = qcut(F^*, 10)
```

其中：

- `G0` 是低因子值组。
- `G9` 是高因子值组，也就是头组。
- 为避免大量相同因子值导致 `qcut` 失败，会加入极小随机噪声，默认标准差为 `1e-8`。
- 默认没有固定随机种子，因此完全复跑时，边界相同值附近的分组可能有极小差异。

第 `g` 组在交易日 `t` 的零费率收益为：

```text
R_{g,t}^{gross} = mean_{i in G_{g,t}}(R^{OTO}_{t,i})
```

训练期多空收益差为：

```text
LongShortSpread = sum_t(R_{G9,t}^{gross} - R_{G0,t}^{gross})
```

该指标使用零费率收益，主要衡量因子排序是否能稳定区分头尾组。

## 9. 手续费与超额 Sharpe

手续费按日期配置：

```text
fee_rate(t) =
  0.0007,  if t <= 2023-12-31
  0.00035, if t >= 2024-01-01
```

组内换手费按成员变化估算。对某个组合 `P`：

```text
turnover_fee_t =
  |P_t - P_{t-1}| * 2 * fee_rate(t) / max(|P_t|, |P_{t-1}|)
```

其中 `|P_t - P_{t-1}|` 表示新进入当前组合的股票数量。乘以 2 表示买入和卖出两边成本。

头组扣费收益：

```text
R_{head,t}^{net} = R_{G9,t}^{gross} - turnover_fee_{G9,t}
```

基线使用评估股票池的全市场等权收益：

```text
R_{bench,t}^{gross} = mean_{i in Universe_t}(R^{OTO}_{t,i})
```

默认基线也扣成员变化费：

```text
R_{bench,t}^{net} = R_{bench,t}^{gross} - turnover_fee_{bench,t}
```

头组相对基线的日超额收益：

```text
R_{excess,t} = R_{head,t}^{net} - R_{bench,t}^{net}
```

超额 Sharpe：

```text
ExcessSharpe = sqrt(252) * mean_t(R_{excess,t}) / std_t(R_{excess,t})
```

## 10. IC 衰减与半衰期

IC 衰减用于观察因子信号对未来多个交易日收益的有效性。默认最大滞后为 20 个交易日。

对滞后 `lag = k`：

```text
ICDecay_k = mean_t Corr_i(F^*_{t-1,i}, R^{OTO}_{t+k-1,i})
```

半衰期定义为：从 `lag=1` 开始，找到第一次连续 3 个 lag 的 IC 都低于首日 IC 一半的位置。

```text
threshold = ICDecay_1 / 2
half_life = first k such that
  ICDecay_k <= threshold,
  ICDecay_{k+1} <= threshold,
  ICDecay_{k+2} <= threshold
```

如果 20 个 lag 内没有满足条件，则记录为：

```text
>20
```

IC 半衰期只报告，不作为硬门槛。

## 11. 硬筛选门槛

训练期必须同时通过以下 4 个硬门槛，因子状态才会是 `passed`：

| 指标 | 公式/口径 | 默认门槛 |
| --- | --- | ---: |
| IC | `abs(mean_t(IC_t))` | `>= 0.03` |
| ICIR | `abs(mean_t(IC_t)) / std_t(IC_t)`，非年化 | `>= 0.5` |
| 多空收益差 | `sum_t(G9_t - G0_t)`，零费率 | `>= 0.30` |
| 超额 Sharpe | 扣费头组相对扣费等权基线，年化 | `>= 1.0` |

训练未通过时：

- 保留公式、代码、因子值、指标和反馈。
- `evaluation_v2.status = failed`。
- `lifecycle.active = false`。
- 默认不运行验证期。

训练通过时：

- `evaluation_v2.status = passed`。
- `lifecycle.status = candidate`。
- `lifecycle.active = true`。
- 继续运行验证期。

## 12. 验证期指标与退化率

验证期使用训练期固定下来的 `direction_multiplier`，不重新选方向。验证期不是硬门槛，主要用于观察因子是否从训练期延续到 2025H2。

对可比较指标，记录保留率和退化率：

```text
retention_ratio = validation_value / training_value
degradation_ratio = 1 - retention_ratio
```

当前比较的指标包括：

- `directional_ic`
- `icir`
- `long_short_spread`
- `excess_sharpe`

如果训练值为 0 或某一侧缺失，则对应保留率记为 `null`。

## 13. 覆盖率与子区间

覆盖率只做提示，不做硬门槛。默认告警阈值：

```text
day_ratio < 0.90
median_stock_count < 1000
```

覆盖率字段：

```text
valid_days       = 因子成功对齐的交易日数
expected_days    = 评估区间内应有交易日数
day_ratio        = valid_days / expected_days
median_stock_count / min_stock_count / max_stock_count
```

训练期还会拆分子区间观察稳定性：

```text
2023
2024
2025H1
```

子区间指标只报告，用于判断因子是否严重依赖单一年份或单一市场阶段。

## 14. 去重规则

去重只在训练通过且 `active=true` 的因子之间进行，并按 `planning_direction` 分组。不同研究方向的因子不会直接互相比。

对两个因子 `A`、`B`，在训练期每天计算横截面相关，然后取日均：

```text
PearsonDup(A, B) = mean_t Corr_i(F^A_{t,i}, F^B_{t,i})
SpearmanDup(A, B) = mean_t SpearmanCorr_i(F^A_{t,i}, F^B_{t,i})
```

如果任一绝对相关达到阈值：

```text
abs(PearsonDup) >= 0.70
or abs(SpearmanDup) >= 0.70
```

则进入疑似重复报告。系统推荐保留训练期 `excess_sharpe` 最高的因子，其余作为 `recommended_archive`。只有人工确认后，才会把重复因子标记为：

```text
lifecycle.status = duplicate_rejected
lifecycle.active = false
```

去重不会删除因子记录、代码、缓存或评估产物。

## 16. 运行方式

运行前需要配置 Mongo 连接信息：

```bash
export MONGO_URI="mongodb://..."
export MONGO_DB="..."
```

只评估尚未写入 `evaluation_v2` 的因子：

```bash
python -m quantaalpha.evaluation.cli evaluate-library \
  --library data/factorlib/all_factors_library.json \
  --mode unevaluated \
  --config configs/evaluation.yaml
```

重新评估全部因子：

```bash
python -m quantaalpha.evaluation.cli evaluate-library \
  --library data/factorlib/all_factors_library.json \
  --mode all \
  --config configs/evaluation.yaml
```

只评估指定因子：

```bash
python -m quantaalpha.evaluation.cli evaluate-library \
  --library data/factorlib/all_factors_library.json \
  --factor-id FACTOR_ID \
  --config configs/evaluation.yaml
```

刷新市场行情缓存后评估：

```bash
python -m quantaalpha.evaluation.cli evaluate-library \
  --library data/factorlib/all_factors_library.json \
  --mode unevaluated \
  --config configs/evaluation.yaml \
  --refresh-market-cache
```

单独生成去重报告：

```bash
python -m quantaalpha.evaluation.cli dedup-report \
  --library data/factorlib/all_factors_library.json \
  --config configs/evaluation.yaml
```

人工确认去重报告后归档重复因子：

```bash
python -m quantaalpha.evaluation.cli archive-duplicates \
  --report data/results/dedup_reports/dedup_YYYYMMDD_HHMMSS_xxxxxx.json \
  --factor-id FACTOR_ID_TO_ARCHIVE \
  --config configs/evaluation.yaml
```

## 17. 状态解释

常见状态：

| 状态 | 含义 | 是否可重试 |
| --- | --- | --- |
| `passed` | 训练期 4 个硬门槛全部通过 | 不需要 |
| `failed` | 训练期门槛未通过，或评估过程发生不可重试错误 | 通常不需要 |
| `lookahead_rejected` | 防未来审计失败 | 需修改因子 |
| `data_error` | Mongo、行情、`result.h5` 等数据问题 | 可以 |
| `skipped_training_failed` | 训练未通过，验证期跳过 | 不需要 |
| `duplicate_rejected` | 人工确认后的重复因子归档状态 | 不需要 |

判断一个因子是否进入候选池时，建议同时看：

```text
evaluation_v2.status == "passed"
lifecycle.active == true
oos_status == "sealed"
```

------

新版不是“模型回测”，而是“单因子 OTO 评估”。每个因子独立评估，不训练 LightGBM，不合成组合。信号用上一交易日因子值，交易收益用公司定义的 OTO 标签：

```text
F(t-1) -> open(t) -> open(t+1)
OTO(t,t+1) = close(t)/open(t) * open(t+1)/pre_close(t+1) - 1
```

训练期是 2023-01-01 到 2025-06-30，验证期是 2025-07-01 到 2025-12-31，2026 数据封存不用。训练期必须同时通过 `abs(IC) >= 0.03`、`ICIR >= 0.5`、`G9-G0 累计收益差 >= 0.30`、`扣费头组相对等权基线超额 Sharpe >= 1.0`。训练通过后才跑验证期，验证只观察退化，不作为硬淘汰。最后同一研究方向下相似度超过 0.7 的因子进入去重报告，人工确认后只保留训练期超额 Sharpe 更高的那个。
