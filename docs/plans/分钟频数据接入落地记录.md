## 阶段记录

### 阶段 1：实现边界和数据口径

- 按已确认记录使用 `min_1` 作为分钟权威数据源。
- `09:30` 按开盘价 bar 处理，`15:00` 按 `(14:59, 15:00]` bar 处理。
- 数据每日早上 10 点获取前一交易日，因此只计算已完整入库的历史日期。

### 阶段 2：分钟读取和数据检查

- 新增只读 `min_1` 读取器，按交易日和股票小批量读取，不写 MongoDB。
- 仅接受沪深 A 股代码，排除北交所、指数和 B 股。
- 在内存中统一两种时间字符串；同值重复去重，冲突重复、非 241 根、必需字段缺失均跳过该股票当天，不填数。
- 新增 `scripts/scan_minute_data_quality.py`，可做全市场只读扫描，本地只保存汇总数和少量异常样例。

### 阶段 3：分钟算子和两阶段执行

- 分钟算子单独放在 `quantaalpha/factors/minute/operators.py`，不混入原日频算子库。
- 已落地方案表格中的分钟滚动、时段统计、回归、MACD、RSI、布林带、衰减和分钟转日频算子。
- 公式中分钟字段用 `$m_open/$m_close/$m_volume` 等名称，日频字段仍使用 `$open/$close/$pe_ttm` 等原名称。
- 执行器先找出并计算分钟分支，归约成每股每日一个值后，再与日频字段合并并运行日频算子。
- 同批公式共用当次内存中的原始分钟数据；一个日期计算完后释放，不建分钟缓存、不保存分钟中间特征。
- 强制每个分钟分支显式用 `M_SESSION_*` 或 `M_TO_DAILY` 结束，并拒绝在分钟阶段内调用日频滚动算子。

示例：

```text
RANK(M_SESSION_RETURN(M_SLICE($m_close, 1430, 1500)))
  * RANK(1 / ($pe_ttm + 1e-8))
```

### 阶段 4：复权、防未来和评估

- 分钟 OHLC 使用当日 `Stock_Adj_<year>.adj_factor`，不使用未来最新复权因子；成交量和成交额不复权。
- 日频数据生成也同步改为当日复权，避免分钟价格和日频价格口径不一致。
- 分钟延迟和变化算子已加入防未来静态检查；现有按日截断重算检查会同时限制 Mongo 查询到截止日。
- 最终仍输出日频 `result.h5`，额外只记录小型覆盖率汇总，不落地分钟数据。
- 评估保持 `F(t) → open(t+1)`，整体调仓周期已设为 3 个交易日。
- 因子生成 Prompt 已加入分钟字段、算子、归约规则和分钟+日频公式示例。

## 遇到并修复的问题

- GitHub 首次推送超时：本地快照提交成功，不影响回溯；完成后再重试推送。
- 分钟与日频字段同名会无法判断计算阶段：落地为 `$m_*` 分钟命名空间，日频原公式不变。
- 单纯把分钟算子加到原执行器会一次读全部历史数据：改为按日读取，且同批公式共用原始 bar。
- 原日频数据生成未应用复权因子，会与分钟价格口径不一致：已在日频构建时使用当日复权因子统一 OHLC 和 VWAP，成交量/成交额不变。
- 实机 MongoDB 验证时返回 `Network is unreachable`：没有改用其他数据源，也没有绕过只读规则；已保留可重复执行的扫描脚本和端到端入口。
